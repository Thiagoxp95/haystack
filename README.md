# Haystack

**Esporte para Todos** news app (pt-BR): a **Convex** backend shared by a **TanStack Start** web app and an **Expo** iOS/Android app. Content comes from the Esporte para Todos **WordPress** ([esporteparatodos.com](https://esporteparatodos.com)), which stays the CMS. The mobile app copies the MacMagazine iOS app (v5) screen for screen; only the brand and content differ. Expo push notifications for breaking stories.

This README is written for AI coding agents (and humans) working on the template. Read it fully before changing code.

| Layer | Tech | Version |
|---|---|---|
| Monorepo | pnpm workspaces + Turborepo | pnpm 12.6, turbo 2.11 |
| Backend | Convex | 1.46 |
| Web | TanStack Start (React, file routes, Vite) | start 1.168, router 1.170, Vite 8 |
| Mobile | Expo SDK 57 + expo-router + expo-notifications | RN 0.86, React 19.2.3 |
| Language | TypeScript | 7.0 (web, backend) · 6.0 (mobile, pinned by Expo) |
| Lint | oxlint | 1.86 |

## Setup

Requires Node 22+ and pnpm (`corepack enable`).

1. Install: `pnpm i`
2. Start Convex (keep it running — it watches and deploys `convex/` and regenerates `_generated/`):
   ```sh
   cd packages/backend && npx convex dev
   ```
   It logs you in, creates a project, writes `packages/backend/.env.local`, and prints the deployment URL.
   No account? `CONVEX_AGENT_MODE=anonymous npx convex dev` runs a local backend at `http://127.0.0.1:3210`.
3. Point both apps at that URL:
   ```sh
   cp apps/web/.env.example apps/web/.env.local        # set VITE_CONVEX_URL
   cp apps/mobile/.env.example apps/mobile/.env.local  # set EXPO_PUBLIC_CONVEX_URL
   ```
   For a phone on your LAN with a local backend, use your computer's LAN IP, not `127.0.0.1`.
4. Load content: `pnpm --filter @haystack/backend refresh` (newest 100 posts; the cron keeps it fresh). Whole archive once: `npx convex run news:refresh '{"pages": 10}'`
5. Run:
   - Web: `pnpm dev` → http://localhost:3000
   - Mobile: development build, not Expo Go (native modules: blur, WebView, AsyncStorage): `cd apps/mobile && pnpm exec expo run:android` (or `run:ios`), then `pnpm --filter mobile start --dev-client`

**No Convex?** Leave `EXPO_PUBLIC_CONVEX_URL` unset: the mobile app reads WordPress directly (feed, categories, article, search). Push needs Convex and is skipped.

| Env var | Where | What |
|---|---|---|
| `VITE_CONVEX_URL` | `apps/web/.env.local` | Convex deployment URL |
| `EXPO_PUBLIC_CONVEX_URL` | `apps/mobile/.env.local` | Same URL. Optional: unset = WordPress direct |
| `CONVEX_DEPLOYMENT` | `packages/backend/.env.local` | Written by `convex dev`; don't edit by hand |
| `EXPO_ACCESS_TOKEN` | Convex dashboard → Environment Variables | Optional; only if Expo "enhanced push security" is on |

## Content: WordPress

- The CMS is the Esporte para Todos WordPress. Its address lives in one place: `WP_BASE_URL` in `packages/backend/convex/wp.ts`. The REST API used: `/wp-json/wp/v2/posts?_embed` (author and featured image come from `_embed`), `/categories`, and `?search=`.
- `pnpm --filter @haystack/backend refresh` (= `npx convex run news:refresh`): mirrors the newest 100 posts and all categories into Convex, keyed on the WordPress id (`wpId`). Edits in WordPress overwrite the mirror. Pass `{"pages": N}` to backfill N×100 posts.
- `convex/crons.ts` runs `refresh` every 30 minutes.
- Titles, excerpts, author and category names are entity-decoded (`decodeEntities`); `body` stays rendered HTML. Mobile renders it in a WebView (YouTube embeds play inline); web renders it with `dangerouslySetInnerHTML` (trusted: it's our own CMS).
- Categories are WordPress's own. There is no hard-coded list anywhere.
- Search always asks WordPress (`?search=`), so it covers the whole archive in both modes.
- Tests: `pnpm --filter @haystack/backend test` (entity decoding + post normalization).

## Push notifications

Flow: **app launch → permission → Expo push token → `push:register` mutation → `pushTokens` table**. When `news:refresh` inserts articles published in the last 2 hours, it calls `push:sendBreaking` for up to 3 of them, which POSTs to `https://exp.host/--/api/v2/push/send` in batches of 100. Tapping a notification opens `/article/[id]`. Tokens Expo reports as `DeviceNotRegistered` are deleted automatically.

- **Category subscriptions:** `pushTokens.categories` (WordPress category ids) is optional. Absent/empty = everything. To subscribe a device: `registerForPush([1367, 1362])` from `apps/mobile/src/push.ts`. Calling it without `categories` keeps the existing subscription.
- **To make it work on a device:**
  1. `cd apps/mobile && pnpm dlx eas-cli init` — writes the EAS `projectId` into `app.json`. Without it the app skips registration and logs a warning.
  2. Change `ios.bundleIdentifier` / `android.package` in `app.json` from `com.example.haystack`.
  3. Use a physical device. Android needs a development build (`pnpm dlx expo run:android` or `eas build --profile development`) because Expo Go doesn't support remote push on Android. iOS push needs an Apple developer account; EAS sets up the credentials.
- **Test without waiting for news:** `npx convex run push:sendBreaking '{"articles":[{"id":18908,"title":"Test","category":"Eventos","categoryIds":[1872]}]}'`
- Tuning lives at the top of `convex/news.ts`: `BREAKING_WINDOW_MS`, `MAX_PUSHES_PER_REFRESH`.

## Conventions

- **Convex is the only backend.** No API routes or server functions in the web app; all data goes through `api.*` queries and mutations.
- **Public vs internal:** anything the apps call is `query` / `mutation`. Anything that writes in bulk, calls the network, or costs money (`refresh`, `upsert`, `saveCategories`, `sendBreaking`) is `internal*`, so it can't be called from a browser.
- **Validate at the boundary:** every function has `args` validators. Route params are untrusted strings; the apps turn them into numbers (`Number(id) || -1`) and `articles.get` returns `null` for an unknown WordPress id ("not found" UI).
- **Indexes, not filters:** query with `.withIndex(...)` (`by_publishedAt`, `by_wpId`). The one exception is the category feed, which scans the mirror newest-first (see `ponytail:` in `articles.ts`).
- **One React version.** Web pins React to the exact version Expo pins (19.2.3) so the hoisted `node_modules` holds one copy. When Expo upgrades React, bump web to match.
- **Styling:** web uses plain CSS with tokens on `:root`. Dark mode follows the OS unless the visitor clicks the header toggle, which sets `html[data-theme]` and remembers it in `localStorage`. Headings use Exo 2, body Rubik (Google Fonts, linked in `__root.tsx`). Green accent `--accent`; change the brand in `SITE_NAME` (`components.tsx`) and the `.logo-mark`. No Tailwind, no CSS-in-JS. Mobile uses `StyleSheet` plus `useColors()` (`src/theme.ts`): iOS system colors, real dark mode everywhere, Inter as the SF Pro stand-in. Mobile sizes come from MacMagazine's SwiftUI source; `src/ui.tsx` names the Swift file each number comes from. Keep them.
- **Loading states:** `useQuery` returns `undefined` while loading and `null` when the query returns null. Handle both.
- **Generated files are committed and never hand-edited:** `apps/web/src/routeTree.gen.ts`, `packages/backend/convex/_generated/*`.

## How to…

### Add a page (web)
Create a file in `apps/web/src/routes/`. The name is the URL: `about.tsx` → `/about`, `team.$id.tsx` → `/team/:id`.
```tsx
import { createFileRoute } from "@tanstack/react-router";
export const Route = createFileRoute("/about")({ component: () => <main className="container">…</main> });
```
`pnpm dev` (or `pnpm build`) regenerates `routeTree.gen.ts`. Commit it.

### Add a screen (mobile)
Create a file in `apps/mobile/src/app/`, e.g. `about.tsx` → `/about`. Register header options in `src/app/_layout.tsx` if needed. Navigate with `<Link href="/about">` or `router.push("/about")`.

### Add a query or mutation
1. Add it to a file in `packages/backend/convex/` (new file = new namespace: `convex/teams.ts` → `api.teams.*`):
   ```ts
   export const byAuthor = query({
     args: { author: v.string() },
     handler: (ctx, { author }) => ctx.db.query("articles").filter((q) => q.eq(q.field("author"), author)).take(20),
   });
   ```
   (Add an index if the table grows, then use `.withIndex`.)
2. With `convex dev` running, `_generated/api.d.ts` updates on save.
3. Use it in either app: `useQuery(api.articles.byAuthor, { author: "Michel Correa" })`.
4. Schema changes go in `convex/schema.ts`. Add new fields as `v.optional(...)` first if data already exists.

### Add a category
Create it in WordPress. The next `refresh` (or the mobile app in WordPress-direct mode) picks it up; nothing in code changes.

### Point at another WordPress
Change `WP_BASE_URL` in `packages/backend/convex/wp.ts`, then run `refresh`.

## Rules for agents

**Do**
- Read the relevant file before editing; match its style (2-space indent, double quotes, semicolons).
- Keep `WP_BASE_URL` the only place the CMS address appears.
- Run `pnpm typecheck && pnpm lint` (and `pnpm build` if you touched web) before saying you're done.
- Install mobile packages with `pnpm exec expo install <pkg>` from `apps/mobile` so versions match the Expo SDK.
- Read `apps/mobile/AGENTS.md` and the versioned Expo docs before touching Expo APIs. Expo changes every SDK.

**Don't**
- Don't edit `convex/_generated/*` or `routeTree.gen.ts` by hand.
- Don't commit `.env.local` files or put secrets in `EXPO_PUBLIC_*` / `VITE_*` vars. Those ship to clients.
- Don't make `refresh`, `upsert`, `saveCategories` or `sendBreaking` public.
- Don't add a second data layer (REST, tRPC, React Query cache) next to Convex.
- Don't bump `react`, `react-native` or `typescript` in `apps/mobile` by hand. Use `expo install --fix`.

## Deploying

- **Backend:** `cd packages/backend && npx convex deploy`. The cron starts automatically on the production deployment.
- **Web:** `pnpm build` outputs `apps/web/dist`. For a specific host (Vercel, Netlify, Node, Cloudflare), add the matching adapter per the TanStack Start hosting docs (usually the `nitro` Vite plugin). Set `VITE_CONVEX_URL` at build time.
- **Mobile:** `pnpm dlx eas-cli build` / `eas submit`, with `EXPO_PUBLIC_CONVEX_URL` set in EAS environment variables.

## Known limits

- Web data loads on the client: SSR renders the layout and a skeleton, then Convex fills it in. For SSR'd data, add `@convex-dev/react-query` and route loaders.
- `push:allTokens` loads every token per send. Fine to a few thousand devices; paginate beyond that.
- The Convex mirror filters a category by scanning newest-first. Fine to a few thousand posts; add a join table past that.
- No infinite scroll yet: feeds show the newest 60 posts.
- Phase 2 (not built): widgets, Watch, podcasts, live scores, in-app purchases.
